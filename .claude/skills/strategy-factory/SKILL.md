# 策略生产

**产出物是「策略」,不是「结论」。**

一个可复用的量化策略 = 代码 + 经搜索验证的参数 + **明确的适用范围** + 失效条件。
只说"腾讯上双均线亏了 21%"不是策略生产,那是单点验证。

---

## 与 strategy-review 的分工

| | [strategy-review](../strategy-review/SKILL.md) | **本 skill** |
|---|---|---|
| 输入 | 一个标的 + 一组给定参数 | 一个假设 + **参数空间** + **标的池** |
| 过程 | 回测一次 | **搜索**:多参数 × 多标的 × 训练/测试分期 |
| 输出 | 该不该在 X 上用 Y | **可部署的策略卡** |

**先用本 skill 生产,再用 strategy-review 评审产出物。**

---

## 铁律

1. **参数必须来自搜索,不能拍脑袋。**
   曾经用 `fast=10/slow=30` 单点回测腾讯得出 REJECT —— 那什么都没证明,
   因为参数是随手定的。换组参数可能就是赚的。**未经搜索的结论无效。**

2. **单标的最优 ≈ 过拟合。** 要找的是在标的池里**稳定**的参数,
   宁可平均收益低一点,也要方差小。见步骤 ⑥。

3. **必须有样本外验证。** QuantDinger 的 `oosValidation` 默认开启(70/30
   训练/测试),**不要关掉它**。训练集上的漂亮数字毫无意义。

4. **REJECT 是有价值的产出。** 搜遍参数空间仍不达标 → 如实结论
   「该策略族不适用于该标的池」,这比硬挑一组好看的参数诚实得多。

---

## 步骤 ① · 提出假设

假设来自洞察([daily-scan](../daily-scan/SKILL.md))或用户指定,必须是**可证伪**的:

- ✅「港股科技股普涨,趋势跟随应能捕捉」
- ✅「建行波动率放大但价格不动,均值回归应能获利」
- ❌「找个能赚钱的策略」(不可证伪,无法设计搜索空间)

写清**为什么现在提这个假设** —— 后面写进策略卡的「适用条件」。

---

## 步骤 ② · 设计参数空间

不是填一个数,是给一个**范围**。

```json
"parameterSpace": {
  "indicator_params.fast_period": [5, 8, 10, 15, 20],
  "indicator_params.slow_period": {"min": 20, "max": 60, "step": 10}
}
```

> 🚨 **key 必须带 `indicator_params.` 前缀。** 写成裸 `fast_period` 会被
> **静默忽略** —— 任务照常 succeeded、照常返回 N 组"结果",但每组参数都是
> 默认值,评分完全相同。实测踩过:16 组变体全部返回 42.1 分。
>
> **自检方法**:结果里如果所有 `overallScore` 都一样,或 `overrides.indicatorParams`
> 为空,就是前缀写错了 —— **不要拿这种结果做任何判断**。
>
> 风控参数用 `strategy_config.risk.stopLossPct`、仓位用
> `strategy_config.position.entryPct`,同样需要前缀。

三种写法:显式列表 `[5,8,10]` / 区间 `{"min":20,"max":60,"step":10}` / 标量 `10`(固定)。

**设计原则**:
- 参数间要有**经济含义上的区分度**,别扫 fast∈{10,11,12} 这种无意义的邻域
- 组合数控制在 `maxVariants`(默认 48)以内,否则会被截断
- 快线必须显著小于慢线 —— 无意义组合会浪费预算,可在筛选阶段剔除

---

## 步骤 ③ · 选标的池

**至少 3 个标的**,否则谈不上稳健性。来源:

- 持仓(`scripts/futu_positions.py`)—— 你有敞口的
- 关注池(`configs/watchlist.yaml`)
- 同一逻辑归属的一组(如"港股科技股":00700 / 09988 / 03690 / 01810)

**标的池要有共性**。把银行股和科技股混在一起搜出的"稳健参数",大概率两边都不好。

---

## 步骤 ④⑤ · 提交搜索

对**每个标的**各跑一次 structured-tune(它一次只处理一个标的):

```
submit_structured_tune(
  base = { code, market, symbol, timeframe:"1d", start_date, end_date },
  parameterSpace = {...},
  evolution = { method:"grid", maxVariants:48 },
  oosValidation = true,      # ← 默认就是 true,别关
  includeBaseline = true
)
```

`method` 可选 `grid`(穷举,推荐起步) / `random` / `de`(差分进化) / `tpe`(贝叶斯)。
参数组合多时用 `random` 或 `tpe` 更省。

返回 `job_id` → `wait_for_job` 或 `stream_job_until_done`。

**OOS 机制**:前 70% 窗口训练调参,后 30% 用 top-K 重新回测。
窗口太短会自动关闭 OOS —— 结果里若显示 OOS 未启用,**必须在策略卡里标明**,
并把该结论的可信度降级。回测窗口建议 ≥ 2 年以保证分割有效。

---

## 步骤 ⑥ · 稳健性筛选 ★ 最关键

**这一步做对了产出的才是策略,做错了产出的是曲线拟合的幻觉。**

把各标的的搜索结果按参数组合对齐,然后:

```
对每组参数 p:
    scores = [标的1 的 OOS 夏普, 标的2 的 OOS 夏普, ...]
    均值   = mean(scores)
    稳定性 = -std(scores)          # 方差越小越好
    最差   = min(scores)           # 最坏情况
    覆盖率 = count(score > 0) / n  # 在几个标的上为正
```

**排序优先级**:
1. **覆盖率** —— 在多数标的上为正才谈得上通用
2. **最差表现** —— 最坏那个标的能接受吗
3. 均值

**绝不能**直接取"某个标的上夏普最高的那组参数"。那是过拟合的定义。

### 危险信号(命中任一,该参数组不可用)

- 只在 1 个标的上好、其它都差 → 巧合
- 训练集夏普 >> OOS 夏普(如 2.5 → 0.3)→ **过拟合确凿**
- 相邻参数表现悬殊(fast=10 好、fast=11 崩)→ 参数敏感,实盘必炸
- 交易笔数 < 10 → 统计不显著(与质疑者同口径)

**参数高原比参数尖峰可靠** —— 一片相邻参数都还行,比单点最优可信得多。

## 步骤 ⑦ · 三角色评审

调 [strategy-review](../strategy-review/SKILL.md) 的评审流程,但**评审对象升级**:

不是"这次回测",而是**整张策略卡**。三个角色要额外审:

| 角色 | 本 skill 特有的审查点 |
|---|---|
| 质疑者 | 参数是搜出来的还是拍的?训练/OOS 差距多大?是尖峰还是高原?标的池够不够? |
| 风险官 | **最差标的**的回撤是多少(不是平均)?最坏情况能承受吗? |
| 投委会 | 适用范围是否说清?失效条件是否明确?记忆层有无同族失败史? |

---

## 步骤 ⑧ · 持久化

评审通过(APPROVE)才存:

```
create_strategy(strategy_name=..., strategy_type="IndicatorStrategy",
                indicator_config={ indicator_code: <代码>, params: <选定参数> })
```

`status` 被后端强制为 `stopped` —— **agent 无权自动启动策略**,启动必须人工操作。这是刻意的安全设计,不要试图绕过。

REVISE/REJECT 的**不要存**,但要写进记忆层(见下)。

## 步骤 ⑨ · 产出策略卡

```markdown
# 策略卡 · 港股科技趋势跟随 v1

**裁决:APPROVE** (综合评分 0.72)

## 假设
港股科技股 2026Q3 普涨,20日动量普遍 +14~20%,趋势跟随应能捕捉主升段。

## 参数(搜索得出,非人工指定)
| 参数 | 值 | 搜索范围 |
|---|---|---|
| fast_period | 8 | [5,8,10,15,20] |
| slow_period | 40 | 20~60 step 10 |

搜索方式:grid,48 组组合 × 4 标的 = 192 次回测;OOS 70/30 已启用。

## 适用范围
- **标的**:港股科技股(已验证 00700/09988/03690/01810)
- **周期**:日线
- **市况**:趋势市。震荡市回撤显著放大 —— 见失效条件

## 绩效(样本外)
| 标的 | OOS夏普 | 收益 | 最大回撤 | 交易 |
|---|---|---|---|---|
| 03690 | 1.12 | +18.3% | -12.1% | 14 |
| 01810 | 0.88 | +14.2% | -15.6% | 12 |
| 09988 | 0.61 | +9.4% | -13.8% | 15 |
| 00700 | 0.34 | +4.1% | -18.2% | 11 |
| **汇总** | **均值0.74 / 最差0.34 / 覆盖率4/4** | | | |

## 失效条件 ★
- 波动率比(近20日/前40日)> 1.8 → 转震荡,趋势策略失效
- 单标的回撤 > 20% → 立即停用该标的
- 连续 5 笔亏损 → 复核市况是否已切换

## 风险
- 最差标的(00700)OOS夏普仅 0.34,勉强及格
- 全部标的回撤均超 12%,需按波动率缩仓
- 样本期仅覆盖一轮上涨行情,**未经历完整熊市检验**

## 三角色意见
<质疑者/风险官/投委会 各自意见>

_本策略卡由自动化系统生成,仅供研究,不构成投资建议。实盘前请自行充分验证。_
```

**「失效条件」是策略卡与回测报告的本质区别** —— 它回答"什么时候该停用",
这是可复用性的前提。没有失效条件的策略不是策略,是一次性的回测记录。

## 沉淀记忆

无论通过与否都写 `data_store/memory/memory.jsonl`,记录**搜索过的空间**:

```json
{"strategy_id":"trend-hk-tech-v1","family":"trend","symbol":"POOL:HK-TECH",
 "outcome":"success","market_context":{"regime":"普涨"},
 "lesson":"趋势族在港股科技池有效:fast8/slow40,OOS均值夏普0.74,覆盖率4/4"}
```

失败也要记 —— **「已搜索过 fast5~20 × slow20~60 全部无效」比没记录有价值得多**,
下次不用重复搜。

## 边界

- ❌ 不启动策略(后端强制 `stopped`,不要试图绕过)
- ❌ 不下单
- ❌ 不因为"想产出一个策略"而放宽稳健性标准
- ❌ 不关闭 `oosValidation`

**搜遍空间没找到有效参数,如实说「该假设不成立」—— 这是合格的产出。**
